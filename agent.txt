> Don't make the templates just "pre-written articles." Make them **structured content block templates** that auto-populate reward-specific information.

That gives you speed when creating rewards while making the final pages much more useful.

# 3. But don't hardcode everything into the template

This is the biggest architectural point.

Your template should contain **blocks**, not one giant text blob.

For example:

```ts
type ContentBlock =
  | {
      type: "text";
      title?: string;
      content: string;
    }
  | {
      type: "code";
      title: string;
      code: string;
      copyable: boolean;
    }
  | {
      type: "image";
      title?: string;
      src: string;
      alt: string;
    }
  | {
      type: "button";
      label: string;
      url: string;
    }
  | {
      type: "qr";
      url: string;
    }
  | {
      type: "status";
      ...
    }
```

Then the template is basically:

```text
[Text Block]
[Reward Details Block]
[Redemption Instructions Block]
[Code Block]
[Button Block]
[Image Block]
[After Claim Block]
[Verification Block]
[Feedback Block]
[Related Rewards Block]
```

This is **much more flexible**.

# 8. Don't copy IGN's text

This is particularly important because you showed me the IGN content.

You can absolutely use the **same factual information**:

> You need a Supercell ID.

> Go to the relevant game store.

> Scroll down.

> Find the redemption section.

Those are facts/instructions.

But don't take IGN's paragraphs and rewrite them sentence-by-sentence.

Instead, make your own concise version based on the actual process.

For example:

### NFR version

> **How to redeem this code**
>
> Sign in to the Supercell Store using the Supercell ID connected to your game account. Select **Clash Royale**, scroll to the bottom of the store page, and enter the code in **Redeem a Store Code**.

Then:

> **1.** Sign in with your Supercell ID.
> **2.** Select Clash Royale.
> **3.** Scroll to the bottom.
> **4.** Enter the code.
> **5.** Return to Clash Royale and check your account.

That's your own concise instructional content.

# 14. One more thing: don't make every block visible just because the template created it

For example, if your QR reward doesn't have special after-claim information, don't render:

> **After claiming**

> Your reward will be added to your account.

if that's just generic filler.

You can have:

```text
AfterClaimBlock
```

but conditionally render it only when it contains meaningful information.

Same with:

* Source
* Promotion
* Expiration
* Screenshots
* FAQ
* Requirements

This is how you avoid falling back into the same problem:

> **"Every page has 500 words because the template requires it."**
